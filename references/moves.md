# Moves catalog

Pick moves that fit the task. Each move lists its **tell** (when to reach for it) and its **trap** (how it fails).

## Altitude: aim at the outcome
| Move | What to do | Tell | Trap |
|---|---|---|---|
| Goal behind the goal | Ask "what should happen after this is done?" twice | The output is an intermediate artifact | Climbing to an empty slogan ("make money") |
| Instance → class | Fix this crash → keep the app crash-free | The same kind of task keeps coming back | Owning an outcome without the wiring to observe it |
| Artifact → decision | Deck → the three most urgent decisions, with for/against | The result will be discussed in a meeting | Deciding for the user. Present options, do not choose |
| Process redesign | Design a better mechanism than the ritual, backtest it on history, run it in parallel | The ritual exists because analysis used to be expensive | Replacing the old mechanism before the parallel run proves the new one |
| Remove the human from the loop | Build the feed, mapping and environment so the agent can keep going alone | The user keeps re-briefing you on the same job | Skipping setup. See Step 7 |

Altitude is weak for purely creative work; say so.

## Depth: work like the best in the field
| Move | What to do | Tell | Trap |
|---|---|---|---|
| Expert instruments | Database, statistical model, profiler, proof assistant, simulator, proper typesetting | You are about to produce a markdown table or prose estimate | Expert vocabulary without the expert method |
| Raw material first | Logs, events, filings, source code, primary datasets, methods sections | You were handed a summary, chart or anecdote | Trusting the digest |
| Unreasonable target | An order of magnitude past the ask, stated as solvable | The ask sets a modest numeric goal | Lowering it at the first resistance |
| Challenge a belief | "We believe X. Reproduce X from the raw data." | The task rests on an untested "everyone knows" | Confirming it with cherry-picked slices |
| New knowledge | Model or simulate the system, find an unknown signal, validate it on held-out data | You are already deep in the data | Reporting in-sample fits as discoveries |
| Outside judge | Tests, benchmarks, held-out data, reproductions, reviewers | Always | Grading your own work |

### Four-question rewrite (Step 3)
1. What would a top professional in this field do here that was not asked for?
2. What is the rawest material they would start from?
3. Which specific methods and tools would they use?
4. What, other than the model or the user, would show the result is right, and what is the pass line?
Then rewrite the task to ask for exactly that: deeper, not bigger.

## Range: borrow other fields' methods
| Move | What to do | Tell | Trap |
|---|---|---|---|
| Nouns → verbs | Restate the artifact as what it must accomplish | The task is named by its format (deck, doc, page) | Verbs that just restate the noun |
| Assemble the crew | "If this had to be excellent, who is on the team?" Pick 3–5 fields | A single-discipline answer leaves value on the table | Too many members. Each must change the plan |
| Red team | Short seller, forensic accountant, attacker, hostile reviewer | Any persuasive or high-stakes output | Strawman objections |
| Methods, not voices | Ask what the practitioner *does* (a short seller's position research), not how they write | Always | Role-play: a weirder transcript and the same result |
| Parallel specialists | Run each field's method in its own subagent and merge | Subagents are available | Merging without reconciling conflicts |

## Anti-patterns (any of these means re-plan)
- The elevated version is just longer, or has more features or more pages.
- The target has no number and no binary check.
- The judge is "I reviewed it".
- The plan needs access or spend that never passed the gate.
- A missed target is reported as success, or quietly replaced with an easier one.
- Escalating something the user explicitly scoped as minimal.
- Retrying a denied action through a different tool.
